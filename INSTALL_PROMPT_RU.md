Установи PAWS в текущий ИИ-клиент, запусти setup и проверь мой аккаунт.

Разрешаю установить только paws-app@paws-app в личные настройки. Сохрани остальные плагины, подключения и настройки. Не создавай и не изменяй дела.

1. Определи текущий клиент и ОС. Используй утилиту текущего приложения и её локальную справку. Другой ИИ-клиент не запускай и не устанавливай. Если нужна зависимость или обновление, дай одно конкретное действие для моей ОС и дождись выполнения.

2. Проверь установку PAWS и его источник: https://github.com/sinister-devs/PAWS-Plugin.git. Если правильный PAWS уже установлен и включён, пропусти установку. Если источник отличается, покажи различие и согласуй замену. Не удаляй старые каталоги и не меняй другие плагины.

3. Для новой установки в Codex: добавь источник, только если его ещё нет, командой codex plugin marketplace add https://github.com/sinister-devs/PAWS-Plugin.git; затем codex plugin add paws-app@paws-app --json. В Claude Code используй только его ветку: claude plugin marketplace add https://github.com/sinister-devs/PAWS-Plugin.git и claude plugin install paws-app@paws-app --scope user. Сверь команды со справкой и проверь фактический результат: PAWS установлен и включён.

4. Прочитай установленный навык setup PAWS. Сначала проверь подключение: если get_my_profile уже доступен и успешно отвечает, повторный вход не нужен. Если нужна авторизация, запомни время начала попытки UTC в ISO-формате и запусти одно штатное подключение встроенного MCP PAWS. В Codex найди его точное имя через codex mcp list --json; для сервера paws-app используй codex mcp login paws-app --scopes paws:mcp,offline_access, если справка текущего клиента поддерживает эту команду. Не добавляй второй MCP-сервер, не выпускай ручные токены и не извлекай сохранённые секреты.

5. Я сам войду на web.pawsagent.app и нажму «Разрешить подключение». В этот момент коротко сообщи: «PAWS установлен. Для подключения проверь аккаунт в открытой странице PAWS, нажми „Разрешить подключение“, затем вернись в этот же чат и напиши „Готово“». Используй штатный инструмент вопроса пользователю с ответами «Готово» и «Не получилось» и свободным текстом. В Codex предпочтителен request_user_input_async. Не заканчивай запрос финальным сообщением, пока я не отвечу: сохраняй сессию авторизации и ожидай через доступный инструмент ожидания (clock.sleep — не более 60 секунд за вызов), без частых проверок. После успешного входа открой в рабочей вкладке PAWS экран https://web.pawsagent.app/connect/complete?since=<время начала входа UTC в URL-кодировке>; если экран ещё не выложен, сохрани стандартное подтверждение входа и ожидание в чате. Дождись моего ответа. После «Готово» проверь ту же попытку и профиль; после «Не получилось» разберись с указанной причиной. Если инструмента ожидания нет, честно сообщи ограничение. Не создавай автоматизации, не запускай второй вход без причины. Пароли, коды, токены и полный адрес возврата в чат не запрашивай и не выводи.

6. После завершения входа вызови get_my_profile именно через подключённый MCP PAWS. Если новых инструментов пока нет в этом чате, не переустанавливай плагин: попроси открыть новый чат, выбрать PAWS и отправить: «PAWS уже установлен. Продолжи setup и вызови get_my_profile. Сначала проверь существующее подключение; повторная установка не нужна. Покажи имя, роль и организацию из ответа. Пока не изменяй дела». Если вход истёк или был отменён, объясни причину и предложи одну новую попытку штатного подключения.

Готовность подтверждай только реальным ответом get_my_profile. Покажи имя, роль и организацию; tenant_id называй «Идентификатор организации», если названия нет. Пока профиль не получен, явно укажи, что уже готово и какое одно действие требуется от меня. Не выдавай успешную установку или вход за завершённую проверку профиля.
